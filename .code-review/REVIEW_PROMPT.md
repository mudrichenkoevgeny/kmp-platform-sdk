## MANDATORY REVIEW CHECKLIST

### 1. Kotlin Style, Explicit API, Type Safety & Multi-Target Constraints
- **Complete Production Code Only:** NO stubs, placeholder code, `TODO()`, dummy implementations, or `// ... rest of code`.
- **Explicit API Mode (`explicitApi()`):** Every public declaration, return type, and `public companion object` in SDK modules MUST specify explicit visibility modifiers and return types.
- **Single Declaration Per File:** Every primary public `interface`, `class`, or `object` MUST reside in its own dedicated file matching its declaration name. Exceptions apply ONLY to direct subtypes of a `sealed` hierarchy and top-level extension parsers/constants directly bound to a `value class` in the same file.
- **NO Trailing Commas** at the end of argument, parameter, or entry lists.
- **NO Agent-Generated Inline Comments (`//`, `/* ... */`) or New `TODO`/`FIXME`:** Logic must be self-documenting via expressive naming and private helper decomposition. Preserve pre-existing developer `// TODO:` / `// FIXME:` comments unless explicitly resolved by the task. **NEVER delete, strip, or omit KDoc (`/** ... */`).**
- **NO Fully Qualified Names (FQN):** Forbidden in expressions, type annotations, generics, and KDoc links. Use `import` or `import ... as ...` aliases. Permitted ONLY inside `@Deprecated(..., replaceWith = ReplaceWith(...))` import parameters or when technically unavoidable (must be justified).
- **Strict Prohibition of `!!`:** Non-null assertion (`!!`) is strictly forbidden in production code (allowed ONLY in test files). Use `?.`, `?:`, `as?`, smart-casts, or `requireNotNull(...)` / `checkNotNull(...)` with descriptive messages strictly for unrecoverable invariants.
- **Control Flow (`when` & `if`):**
  - NO function or suspend calls inside `when (...)` parentheses and NO `when (val x = someCall())`. Extract the call to a `val` on the preceding line first.
  - Exhaustive `when` on `sealed` types and `enum`s without `else` unless logically unavoidable.
  - Mandatory `{ ... }` block braces for all `if` statements (NO single-line `if (cond) return`; put `return` on its own line inside braces).
- **Naming, Function Bodies & Companion Objects:**
  - Concrete domain-focused outcome variable names (`validationResult`, NOT `result` or `data`). DTO properties use `camelCase` with `@SerialName` referencing `*ApiFields` constants.
  - Simple mappers use expression-body (`=`); multi-step or branching logic uses block-body (`{ ... }`).
  - Place `public companion object` at the bottom of the class body (unless implementing `NavigationScreenParamsParser<P>`); extract constants as `public const val`.
- **Domain ID Value Classes & Wire `.value`:**
  - `@JvmInline value class` IDs MUST be `@Serializable`, expose `.value`, `asString()` / `asHexDashString()`, companion `generate()` (when applicable), and `String.toXxxOrNull()` / `String.toXxxOrThrow()` in the same file.
  - Always convert strings via `string.toXxxIdOrThrow()` / `string.toXxxIdOrNull()` and serialize via `.asHexDashString()`. NEVER construct `XxxId(Uuid.parse(string))` directly.
  - Domain enums and extensible interfaces expose `.value` for wire string representation (NEVER `.serialName`).
- **Multi-Target & Source Set Compliance:** Code in `commonMain` MUST be strictly compatible with Android, WasmJs, and iOS — NO JVM-only APIs (`java.util.*`, `java.time.*`, reflection); use `kotlinx-datetime`, `kotlinx-serialization`, `kotlin.uuid`. Assign files and dependencies to the correct source sets (`commonMain`, `androidMain`, `wasmJsMain`, `iosMain`).

### 2. Decompose Architecture, Navigation, Networking, Storage & Errors
- **Layering & Decompose Components (`ui`, `component`, `usecase`, `repository`, `network`, `di`):**
  - Compose UI (`*Screen`) must be stateless and observe Decompose `Value<ScreenState>`.
  - Decompose `*Component` classes own business logic, UI state, and navigation (NO mutable `var` properties exposed), managing async work via `componentCoroutineScope()`.
- **SDK Bootstrap, Networking & WebSockets:**
  - Follow host init sequence: `CommonComponent` -> domain components -> `commonComponent.init()` registering all feature `AppErrorParser`s.
  - Encapsulate feature HTTP behavior in `HttpClientConfigPlugin`. Implement stateless WebSocket handling via `WebSocketMessageHandler` registered on `commonComponent.webSocketService`.
- **Navigation, Deep Links & Back Handling:**
  - Decompose screen destinations with arguments MUST encapsulate them in `@Serializable` `*Params` data classes. Root components expose `navigateTo(destination)` hooks for deep links.
  - Universal deep links use `shared-foundation` `NavigationRoute` / `ParameterizedNavigationRoute<P>`, modular `*DeepLinkParser` / `*UrlFormatter` (with required `baseHost: String`), `toFullUrl()`, and app-specific `*AppDeepLinkRoute` aggregators in `sample*`.
  - `handleBack` uses `navigation.pop()` when `previousConfig == parentDestination`, otherwise uses `navigation.navigate` stack replacement so popped screens trigger `onDestroy()`. Wasm history uses `SetupBrowserHistory(mainComponent, baseUrl)` with `getAncestorPaths()`.
- **Decompose Slot Navigation (`childSlot`):**
  - `<ScreenName>DialogConfig.kt` (`@Serializable sealed class`) and `<ScreenName>DialogChild.kt` (`sealed class`) MUST reside in separate files inside a `dialog/` subpackage with KDoc on all public members.
  - Stateless dialogs use `data object`; stateful dialogs use `data class` wrapping a nested child component.
- **Reactive List Mutations (`ListOwner`) & Pagination:**
  - Define `*ListOwner` interfaces, delegate on stack `Child` wrappers (`ListOwner by component`), and broadcast via `stack.value.items.mapNotNull { it.instance as? ListOwner }.forEach { ... }`.
  - Paged lists MUST use `PaginationState<T>` (`core:common`), transitions (`appendResult()`, `toNextPageLoading()`, `toError()`), `LazyListState.OnBottomReached`, and `PagingFooter`.
- **Storage & Error Pipeline:**
  - Use `EncryptedSettings` from `core/common`. **STRICTLY FORBIDDEN** to import raw platform storage (`SharedPreferences`, `DataStore`, `IndexedDB`, `localStorage`) in feature packages.
  - Domain errors extend `AppError` sealed hierarchies, pass through `AppErrorParser` (falling back to `CommonErrorParser`), and resolve via `LocalErrorParser.current`.
